# Data Readiness Playbook

## Classification
`data_readiness`

## When to Use
- Data is messy, fragmented, or inaccessible
- "We have data but don't know what to do with it"
- Multiple systems with no integration
- Data quality issues blocking analytics projects
- Unclear what's feasible with current data
- Need a roadmap before committing to a project

## When NOT to Use
- Data is already clean, integrated, and accessible
- Problem is clearly defined and data is ready
- When immediate quick wins are more valuable than planning
- Organization isn't ready to act on findings

## What It Is
A diagnostic service that reviews your current data landscape, identifies issues and opportunities, and creates a prioritized roadmap for data-driven improvements.

## Audit Components

### 1. Data Landscape Review
- What systems hold data
- What data exists vs what's needed
- Data access and integration status
- Current data flows

### 2. Quality Assessment
- Completeness (missing values)
- Accuracy (correctness)
- Consistency (across systems)
- Timeliness (how current)
- Uniqueness (duplicates)

### 3. Opportunity Mapping
- Use cases ranked by value and feasibility
- Quick wins vs longer-term investments
- Build vs buy decisions
- Resource requirements

## Simple First Implementation
1. **Stakeholder interviews**: 2-3 sessions to understand goals
2. **Data inventory**: Catalog available data sources
3. **Sample data review**: Assess quality of key datasets
4. **Use case prioritization**: Rank opportunities by ROI
5. **Roadmap creation**: Phased plan with dependencies
6. **Report delivery**: Clear recommendations and next steps

## Deliverables
- Data landscape map
- Quality assessment summary
- Prioritized opportunity list
- Feasibility scores for each opportunity
- Recommended roadmap (phases)
- Quick wins identification
- Risk and dependency notes

## Risks and Mitigations
| Risk | Mitigation |
|------|------------|
| Scope creep during audit | Fixed-time engagement, clear deliverables |
| Stakeholder disagreement | Facilitated prioritization workshop |
| Findings not acted upon | Executive sponsor, clear next steps |
| Over-promising on AI | Honest feasibility assessment |

## QSol Examples
- SME general: "Where should we start with data?" audit
- Manufacturing: Data infrastructure assessment before analytics
- Services: AI readiness audit before assistant project

## Typical Timeline
1-5 days depending on depth

## First Step
"Book a discovery call and we'll assess whether a formal audit is the right starting point for you."

## Audit Checklist

### Data Sources
- [ ] List all systems containing business data
- [ ] Identify data owners for each system
- [ ] Document export/API capabilities
- [ ] Note any data sharing restrictions

### Data Quality
- [ ] Sample key datasets for completeness
- [ ] Check for duplicate records
- [ ] Verify date/time consistency
- [ ] Assess ID matching across systems

### Use Cases
- [ ] Document current pain points
- [ ] List desired analytics capabilities
- [ ] Identify quick win opportunities
- [ ] Assess AI/ML suitability

### Resources
- [ ] Current technical capabilities
- [ ] Available budget
- [ ] Internal champion identified
- [ ] Timeline expectations
